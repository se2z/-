Статус: **кандидат собран; публичный выпуск пока не готов**.

## Клиентский файл

- Файл: `dist/notify_bot.exe`
- Размер: 35,849,216 bytes
- SHA-256: `D98F0E7E9F6F8EA616812FBD0C6EF72A386BCDF0E836108FB7B874360849F844`
- Платформа: Windows x64 GUI
- Подпись Authenticode: отсутствует
- Папка `dist/` содержит только этот файл. Рантайм TDLib и notices встроены в EXE; при первом старте приложение извлекает файлы в `%LOCALAPPDATA%\NotifyBot`.

Раздавать клиентам можно только `dist/notify_bot.exe`, не архив всего каталога проекта. В рабочей конфигурации проекта обнаружены закрытый ключ лицензий, локальные DPAPI-данные Telegram и каталог сессии; они не входят в `dist/` и не должны копироваться в публикацию или отправляться клиентам.

## Проверки

- Чистая конфигурация x64: пройдена, `Visual Studio 17 2022`, MSVC `19.44.35230.0`, SDK `10.0.26100.0`.
- Сборка `notify_core`, `notify_bot`, `notify_admin`, `notify_cli`, `notify_tests`: пройдена.
- `ctest --test-dir build_release -C Release --output-on-failure`: `100% tests passed, 0 tests failed`.
- `dist/notify_bot.exe` совпадает с результатом чистой сборки по SHA-256.
- PE проверен как `x64`, `/SUBSYSTEM:WINDOWS`; импортируемые DLL — системные Windows-библиотеки. TDLib и её runtime-зависимости вложены в EXE.
- Добавлены настройки интервала между стартами отправок и cooldown между ручными циклами; сохранение настроек собрано, интервал `SendGuard` покрыт unit-тестом. UI-поток и реальная доставка в Telegram отдельно не прогонялись.

## Что блокирует публичный выпуск

1. EXE не подписан сертификатом Authenticode. Публично распространять как проверенный издателем файл можно только после получения и применения доверенного сертификата подписи.
2. Не проводился живой end-to-end прогон в чистом профиле Windows 11: вход Telegram, код и 2FA, каждый поддерживаемый формат прокси, отправка текста и фото, фильтр согласия, остановка и возобновление очереди. Локальные unit-тесты этого не подтверждают.
3. Измерения Premium-поля и перехода в `PREMIUM_EXPIRED`, шаблоны разбора статуса `@SpamBot`, `entity_unit` и `custom_emoji_document_id` остаются `unset`; соответствующие функции нельзя обещать клиентам до подтверждения на указанной сборке и заполнения конфигурации по рецепту в `README.md`.
4. `admin_chat` и `event_sink` не заданы. Поэтому автоматическое личное уведомление владельцу после `PREMIUM_EXPIRED` не подтверждено; событие сохраняется локально.
5. Отзыв лицензий сейчас локальный (`state/revoked.jsonl`) и сам по себе не синхронизируется с уже установленными клиентами. Нельзя обещать удалённый отзыв ключей без отдельного механизма доставки списка отзыва.
6. Проверка согласия читает локальный `state/subscribers.jsonl`; она не сверяет записи с независимым источником. Получатели должны иметь явное согласие, а клиентскую проверку нельзя описывать как серверную гарантию.
7. Перед публичной публикацией нужно подготовить политику конфиденциальности и канал поддержки: приложение хранит сессию на компьютере пользователя и отправляет выбранные сообщения через его Telegram-аккаунт.

## Повторная сборка

Из корня `notify_bot/` в x64 Developer PowerShell:

```powershell
cmake -S . -B build_release -A x64
cmake --build build_release --config Release --parallel
ctest --test-dir build_release -C Release --output-on-failure
Copy-Item build_release\Release\notify_bot.exe dist\notify_bot.exe -Force
Get-FileHash dist\notify_bot.exe -Algorithm SHA256
```
